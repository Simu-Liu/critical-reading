# 指定论文阅读工作流

## 1. 先确认现状

确认用户指定论文与活动Vault。按type和父条目key找已存在AI/全文/个人页，避免仅按标题创建重复笔记。首次读取已有页面时检查实际文件是否重命名，frontmatter或正文链接是否仍指向旧目录。

新文件只用 `vault/`、`fulltext/`、`Notes/`。更新用户指定的同一论文可以修复它的路径属性与可核验导航链接；不要批量移动其他文件。任何不能用稳定身份唯一解决的旧路径停止写入，不猜相似标题。旧技能目录约定不适用于本技能。

新建文件名使用Windows与Obsidian双链都能解析的字符，避开`#`、`^`、`[`、`]`、`|`等链接分隔符；论文title属性及显示题名仍保留原文。已有文件若含这些字符，不能在保持其原样的同时声称脚本导航已验证，应先选用可正确联动的路径方案。

仅创建Skill或调整模板的任务不运行真实论文流水线。对真实既有文献的重写须在阅读/更新任务范围内。测试Skill用隔离Vault，避免产生假论文或测试笔记污染真实文献目录。

## 2. Zotero身份与可用材料

按 [zotero-acquisition.md](zotero-acquisition.md) 核实父条目和PDF。复用正式全文或与两个key吻合的MinerU转换结果；读取 `_llm_source.json` 或等效来源凭据。解析目录序号不是论文身份。

无可访问全文时明确说明缺少材料，不能用摘要补写整篇精读。找不到附图时可以检查原PDF；优先复用已提供MinerU；确实缺转换结果且已有工具可用时交本包全文归档模块及tools/run_mineru_production.py，不擅自安装软件。多个PDF要核实所用版本，不能无条件选择第一个。

## 3. 原文层归档

- 全文写 `fulltext/<collection>/<zotero_key>.md`，图片写同目录 `images/<zotero_key>/`。PDF只读。
- 除frontmatter、可验证定位标记及必要的图片链接修复外，原文正文保持原样。保存来源路径/校验和以及可用的转换时间，不能声称重跑MinerU。
- 全文frontmatter至少含type、title、zotero_key、pdf_key、doi、collection、fulltext_path、note_path（指AI页）、analytical_note_path、personal_note_path、zotero_item、zotero_pdf、source_type、page_mapping。
- 相对图片链接须可解析且留在Vault；Markdown没嵌图但转换器产出图片时，保留资源并在AI对应主图处提供可核对的入口。不得把零图片引用误报为已经检查图像内容。
- `page_mapping: unknown`时禁止从Markdown顺序猜页码，但允许直接核验原PDF页面。

## 4. 图组驱动的AI精读

使用当前 `templates/critical-reading-template.md` 或Skill自带 [AI模板](../assets/analytical-note-template.md)。从Introduction建立Gap，从Results提炼创新和图组推进，而非套用固定数量的创新或强行补出作者未做的实验。

### 分类约定

`article_type`可多选神经、免疫、代谢、组学、药理。`research_relevance`只用相关/不相关，不分相关程度；高质量但不符合用户方向的论文仍可记为不相关。

`research_directions`是唯一研究方向字段，可同时对应多个下列方向：肿瘤相关神经、肿瘤相关血管、中性粒细胞、嗜酸粒细胞、高内皮微静脉/三级淋巴结构、组织损伤及修复、肿瘤T细胞免疫、肿瘤B细胞免疫、膀胱原位免疫、肿瘤疫苗、实体瘤CAR-T。不相关时用空列表，不新增方向字段或用个人idea反推论文方向。

从该列表派生Obsidian与Zotero相同的层级标签：`研究方向/<方向>`；其中方向内部的`/`替换为`-`，例如`研究方向/高内皮微静脉-三级淋巴结构`。保留其他已有标签；更新AI分类时替换对应的派生方向标签，但保留个人页已修改的分类/标签。没有实际写回Zotero就记录待同步；不把生成的标签当作已经同步。

### 创新三项

每个创新点只保留：

1. **创新主张**：一个清楚、可被图表支持的新发现/机制/策略。
2. **与已有研究的差异**：先说明既有研究已经解释到何处，然后给出尚不能解释的现象、缺失因果环节或适用范围，最后说明填补它的意义。引用本文所述前人文献编号；没读过相应全文时写“本文援引”，不能说已独立验证，也不凭印象断言“首次”。
3. **对应科学问题**：连接Gap与新主张。

删掉独立方法/证据小节、创新证据数量总表及独立综合评估章节，避免重复。

### 小图与阶段判断

每个主图面板1–3句话，涵盖真正影响理解的模型/方法、关键分组和结果；可以连续写数个面板，但不得用“A–G”一句概括而隐藏各面板做了什么。不列样本量和重复。药物剂量、表达平台、时序等仅在决定解释时写入。

原文Results完成一个发现/机制环节时就写阶段总结。不能机械地每张大图只总结一次：同一大图可含多个环节，一个环节也可跨图。解释需要包含：

- 当前图组与之前哪些具体面板共同支持哪个创新点的哪一环。
- 相关补图能增加哪一部分支持；只在可访问材料中核验，未取得时保留“正文报告，补图未核验”。
- 作者引用的既有研究贡献的是背景、可能机制还是已知现象，不把文献引用当作本研究实验。
- 当前足以支持何种力度：关联、体外因果贡献、必要性/充分性，或某模型中的概念验证；保留部分救援、相关而非因果等条件。
- AI判断证据还缺什么，给出最有区分力的补充实验及其目的，而非一长串常规实验。

不要设补充图/表独立解析章或台账。可以在阅读范围一句说明缺失材料；在关联图组处点明对该判断的影响。主表按实验/结果逻辑简要解释，不虚构不存在的主表。

### 其他段落

机制证据链区分作者实测、模型支持及待证箭头。结论区优先覆盖Conclusion全部完整句意；没有该节时说明取自Discussion总结段，全部拆解该段，并按需要补充Results关键机制句。原句须真实定位，提供中文、具体证据、推断边界；页码未验证就不用页码。

局限区分作者承认与AI提出。AI后续建议留在AI页并标AI，不写用户第一人称。个人启发/阅读后决定只留真实个人笔记入口，不在AI页代填。关联概念双链可作待建候选，不为每个概念自动创建空壳。

质量分数为五项1–5；0为未评分。AI分数暂定，保留DataviewJS均值/星级计算。无需改Obsidian插件配置，不把文章元数据中的期刊IF当作文章证据评分。

## 5. 个人页和完成检查

按 [关联与作者身份规则](linking-and-authorship.md) 建立个人页，只复制同schema属性和导航，正文留白。已存在时只补缺失关联，保留用户正文、评分与分类。

完成：本次AI页、全文、个人页身份与路径校验；来源引句、所有主图面板覆盖、阶段判断和个人内容保护检查。缺补充材料可以交付“主文已读、补充待核验”，不可写全文100%完成。报告任何实际的校验限制。

新建AI页时，可在当前 `vault/_index` 维护文献导航，查询使用 `FROM "vault" WHERE type = "literature-note"`。不要复用含`02vault`的查询，也不要给`Notes`加`literature-note`标签。个人页不增加论文数量。

正常入库每篇恢复Knowledge决策及适用增量维护；没有持久新知识可记录NO_KNOWLEDGE_CHANGE，不强制建立成熟综合页。技术日志与可读knowledge/log.md分开且只追加；不把个人idea存入论文证据层。
